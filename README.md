# 单场景多世界传送门框架

> Unity Built-in · Stencil 模板测试 · 可见性与资源状态管理

在同一场景里并存多套互相独立的世界，玩家通过一扇门在它们之间穿梭；
门的前后两面分别呈现「目的地」与「来处」，支持双向回望。

核心不是"画一个传送门"，而是**把可见性、碰撞、阴影、照明四类子系统的状态统一仲裁**，
让"看得见的"和"撞得到的 / 照得到的"永远一致。

## 要解决的问题

用 Stencil 做传送门，能解决"看得见哪里"，但解决不了另外三件事：

| 子系统 | Stencil 是否影响 | 不管会怎样 |
|---|---|---|
| **渲染** | ✅ 会 | — |
| **阴影投射** | ❌ 不会 | 看不见的场景往你的世界投影（幽灵阴影） |
| **碰撞体** | ❌ 不会 | 走动时被"空气墙"挡住 |
| **灯光** | ❌ 不会 | 看不见的场景把光漏过来 |

所以需要一层**状态管理**：把每个世界当成一个"组"，任何一个组被激活时，
四类子系统一起切换，而不是只切渲染。

## 架构

```
                     ┌──────────────────────┐
                     │   PortalController   │
                     └──────────┬───────────┘
                                │  RefreshSceneState()   ← 唯一刷新入口
        ┌───────────────┬───────┴────────┬────────────────┐
        ▼               ▼                ▼                ▼
   门遮罩材质      各组比较规则        阴影投射         碰撞体 / 灯光
 (StencilRef)   (Equal/Always/      (ShadowCasting   (enabled)
                   NotEqual)           Mode)
```

### 分区标识

场景里的每个世界 = 一组使用 `Portal/SceneN` 材质（N = 1~10）的渲染器。
控制器启动时扫描材质 shader 名自动分组，**不需要手动登记渲染器**。

### 两态状态机

```
预览态（门外）
   当前世界：Equal      → 只在门框里可见
   其它世界：Equal      → 不可见
   门的遮罩：Ref = 当前世界

进驻态（门内）
   当前世界：Always     → 铺满全屏
   其它世界：Equal      → 不可见
   门的遮罩：Ref = 总站  → 正面门背对你，背面门显示来处
```

### 单一刷新入口

所有状态变更（进 / 出 / 切场景 / 切 Ref）都只调一个方法：

```csharp
void RefreshSceneState()
{
    UpdateDoorMask();            // 门显示谁
    // 逐组：比较规则 + 阴影投射
    // 逐组：碰撞体 + 灯光
}
```

**只有一处刷新逻辑**，杜绝"门切了但碰撞没切"这类状态错位。

## 双向视口

经典做法是"双相机 + RenderTexture"，但它有三笔账：

| 代价 | 说明 |
|---|---|
| 额外相机 | 每扇门一个渲染通道 |
| 分辨率损失 | RT 尺寸通常低于屏幕 |
| 显存占用 | 每扇门一张 RT |

这里用的是**单侧面剔除 + 双写入面**：

```hlsl
// 正面门：显示目的地
Stencil { Ref [_StencilRef]  Comp Always  Pass Replace }

// 背面门：Ref 写死，只显示总站
Stencil { Ref 5  Comp Always  Pass Replace }
```

```hlsl
Cull Back     // 只在能看见正面的那一侧写模板
```

- 正面门的法线朝向总站 → 只有站在总站时才写模板
- 背面门旋转 180° → 只有站在目的地时才写模板
- **两扇门各管一面，永远不会互相覆盖**

代价是：需要自己维护渲染 / 物理 / 照明的一致性（见下一节）。

## 一致性仲裁

三态比较规则是这套系统的关键：

| 规则 | 值 | 用途 |
|---|---|---|
| `Equal` | 3 | 只在门框里可见（预览态 / 非当前组）|
| `Always` | 8 | 铺满全屏（进驻态）|
| `NotEqual` | 6 | **排除**门框区域 |

`NotEqual` 专门解决"门里要显示回望世界、但当前世界会盖住它"的问题：

```
进驻态下：
   当前世界 → Ref = 总站Ref, Comp = NotEqual   → 除门框外全画
   总站     → Ref = 总站Ref, Comp = Equal      → 只在门框内画
```

两者互补，**同一块区域不会重复绘制**。

阴影 / 碰撞 / 灯光跟着同一套 `active` 判定走：

```csharp
bool active = isHub ? (!_inner) : (_inner && refId == activeRef);

renderer.shadowCastingMode = active ? On : Off;
collider.enabled           = active;
light.enabled              = active;
```

## 过渡表现

### 穿门：距离驱动的全屏闪光

`PortalTrigger` 用玩家到门平面的距离驱动进度，越靠近越亮：

```
1.4 m ──────► 0.15 m
进度 0 ─────► 1.0（smoothstep）
```

`PortalScreenTransition` 支持 6 种模式：

| 值 | 模式 |
|---|---|
| 0 | 噪波溶解 |
| 1 | 圆形虹膜 |
| 2 | 水波涟漪 |
| 3 | 漩涡扭曲 |
| 4 | 单向扫屏 |
| 5 | 屏幕闪光 |

### 切场景：噪波溶解换场

```
旧世界 _Dissolve: 0 → 1（溶解掉）
      ↓ 换门遮罩 Ref
新世界 _Dissolve: 1 → 0（溶入）
```

溶解外观参数（噪声尺度、边缘颜色、边缘强度）是**全局 uniform**，
改一次全部场景材质同时生效，不需要逐个材质设置。

## 代码结构

```
PortalDemo/
├── Scripts/
│   ├── PortalController.cs          # 门控制器：分组 / 状态机 / 一致性刷新
│   ├── PortalTrigger.cs             # 穿门检测 + 距离驱动过渡
│   ├── PortalScreenTransition.cs    # 相机后处理过渡（6 种模式）
│   ├── SimpleBloom.cs               # 简易辉光（HDR 亮部 + 分离高斯）
│   └── PortalNoShadow.cs            # 不投影标记组件
└── Shaders/
    ├── Mask.shader                  # 正面门遮罩（写 StencilRef）
    ├── MaskHub.shader               # 背面门遮罩（Ref 写死）
    ├── Scene1~10.shader             # 场景组内容 shader（只差 Ref）
    ├── Scene5_*.shader              # 总站的卡通风格变体
    ├── PortalRim.shader             # 门框边缘光
    ├── ScreenFx.shader              # 屏幕特效（6 种模式）
    └── SimpleBloom.shader           # 辉光 pass
```

## 关键参数

| 参数 | 说明 |
|---|---|
| `Active Ref` | 当前世界编号（1~10）|
| `Hub Ref` | 总站编号，用于回望 |
| `Show Hub Through Back Door` | 开启双向回望 |
| `Hub Passive View` | 总站是"回看副本"时勾选（规则恒为 Equal）|
| `Keep Hub Colliders Outside` | 总站需要被踩到时勾选 |
| `Cross Duration` / `Cross Fx Mode` | 穿门过渡时长与模式 |
| `Scene Switch Duration` | 换场景溶解时长 |
| `Dissolve Scale / Edge Width / Intensity` | 溶解外观 |

场景规模参考：单场景纳管 **4 套目的地、约 4300 个渲染器、3000 个碰撞体**，切换与穿梭均为实时。

## 已知限制

| 限制 | 说明 |
|---|---|
| **单场景** | 所有世界必须在同一个 `.unity` 里，模板测试不跨场景 |
| **玩家坐标不变** | 本质是"换一套可见的世界"，不是真正的场景加载 |
| **Ref 上限 10** | 遮罩材质预生成 10 套；要更多需改为动态创建 |
| **单个门控制器** | 多扇门需要拆成多控制器 + 共享分组数据 |
| **依赖门框形状** | 门的遮罩就是它的网格，异形门需要自定义网格 |
